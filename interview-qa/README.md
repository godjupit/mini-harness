# 面试问答记录规范

这个目录只记录 `INTERVIEW_GUIDE.md` 问题清单中已经实际询问过的问题，不提前批量生成其余问题的答案。临时概念追问、澄清问题和不在问题清单中的问题只在聊天中回答，不创建问答文件。

## 写作要求

1. 一个面试问题对应一个独立的 Markdown 文件。
2. 只有问题清单中的题目才创建文件，文件序号与问题清单保持一致，例如 `01-agent-loop.md`、`02-tool-call.md`。
3. 回答采用直接交流的口吻，效果应该接近用户在对话中临时提问后得到的回答，不写成僵硬的教材或固定模板。
4. 根据问题本身灵活组织内容，不要求每篇使用完全相同的标题和段落。
5. 不在开头集中堆放“需要查看的所有文件”。讲到某段逻辑时，再在对应代码前紧挨着标出具体源码位置。
6. 源码位置必须使用适合 IDE Markdown 预览的相对路径链接，并用 `#L行号` 指向具体起始行，例如：

   ```markdown
   [engine.py：AgentLoop.run()](../src/mini_openharness/engine.py#L180)
   ```

7. 链接下面紧接相关代码、伪代码或解释，避免读者在文件列表和正文之间来回查找。
8. 引用项目真实代码时说明这是“关键代码”；为了突出调用链而简化代码时明确标注为“伪代码”。
9. 代码后要解释它在完整调用链中的作用、设计原因以及关键异常路径，不能只粘贴代码。
10. 优先给出一版可以在面试现场直接说出的回答，再补充帮助理解和记忆的源码分析。
11. 回答只覆盖当前问题真正需要的范围，避免为了显得完整而扩展到无关模块。
12. 源码发生变化后，应同步检查链接行号是否仍然准确。
13. 面试问答文件正常保留在版本工作区中，不写入 `.gitignore`。
