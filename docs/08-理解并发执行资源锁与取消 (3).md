## 2. Tool Protocol 是一份能力合同

```python
class Tool(Protocol):
    name: str
    description: str
    parameters: JsonSchema
    read_only: bool

    async def run(arguments, context) -> ToolResult:
        ...
```

只要一个对象具备这些属性和方法，就能被注册为工具，不要求继承某个基类。

四个元数据分别用于：

```text
name        模型请求和注册表查找
description 告诉模型工具用途
parameters  告诉模型参数格式并用于校验
read_only   权限和资源调度的保守判断
```

## 3. 注册与 Schema 暴露

```python
def register(self, tool):
    if tool.name in self._tools:
        raise ValueError(...)
```

同名工具被拒绝，避免后注册对象静默覆盖前一个。

`schemas()` 只向 Provider 提供模型需要看到的信息，不暴露 Python `run` 方法本身。

## 4. execute 的完整执行栈

`ToolRegistry.execute()` 的顺序：

```text
查找工具
→ JSON Schema 校验
→ 创建/读取权限策略
→ 评估 allow/deny/ask
→ 如需 ask，调用人工审批回调
→ 记录权限 Trace
→ 拒绝或执行
→ 设置超时
→ 把异常转换成 ToolResult
```

这一顺序非常重要：参数不合法时，不应进入真实工具；未获权限时，不应产生副作用。

## 5. JSON Schema 校验

`write_file` 的参数定义：

```python
{
  "type": "object",
  "properties": {
    "path": {"type": "string"},
    "content": {"type": "string"}
  },
  "required": ["path", "content"],
  "additionalProperties": False
}
```

以下调用会失败：

```json
{"path": "a.txt"}
```

因为缺少 `content`。以下也失败：

```json
{"path": "a.txt", "content": "x", "danger": true}
```

因为不允许额外字段。

## 6. 错误作为 observation

函数捕获多类错误，并返回：

```python
ToolResult("...", is_error=True)
```

这样 AgentLoop 可以把错误作为 tool 消息交回模型。模型可能修正参数继续执行。

这与普通命令行程序“异常立即退出”不同。Agent 系统更重视可恢复反馈。

## 7. ToolContext 为什么单独存在

```python
class ToolContext:
    workspace: Path
    allow_write: bool
    permission_policy: PermissionPolicy | None
    approval_callback: ApprovalCallback | None
    tracer: TraceWriter | None
    tool_timeout_seconds: float
```

工具调用不仅需要参数，还需要运行环境。把这些公共依赖收在 Context 中，可以避免每个 `run()` 函数拥有一长串参数。

## 8. 工作区防逃逸

```python
candidate = (root / raw_path).resolve()
candidate.relative_to(root)
```

如果用户或模型传入：

```text
../../etc/passwd
```

解析后的路径不再位于 workspace 内，`relative_to(root)` 抛出异常，工具返回参数错误。

这是“路径穿越”防护。

## 9. 运行时秘密保护

读取工具还拒绝：

```text
.env
.env.local
.mini-oh/oauth/...
```

列表工具也会隐藏这些文件。注意这只是纵深防御的一部分，不能替代正确的权限和宿主机安全。

## 10. 默认工具逐个看

### ReadFileTool

- 只读；
- 检查路径边界和秘密文件；
- 用 `asyncio.to_thread` 避免同步文件读取阻塞事件循环。

### ListFilesTool

- 递归列文件；
- 过滤 `.git`、虚拟环境、缓存和运行目录；
- 最多返回 500 个文件。

### WriteFileTool

- 可变更；
- 自动创建父目录；
- 写入 UTF-8；
- 返回写入字节数。

## 11. 新增一个简单工具的模板

```python
class FileSizeTool:
    name = "file_size"
    description = "Return one workspace file size in bytes."
    read_only = True
    parameters = {
        "type": "object",
        "properties": {"path": {"type": "string"}},
        "required": ["path"],
        "additionalProperties": False,
    }

    async def run(self, arguments, context):
        path = _safe_path(context.workspace, arguments["path"])
        return ToolResult(str(path.stat().st_size))
```

还应实现 `resources()`，声明对该文件的读访问。

## 12. 本章练习

1. 为什么未知工具被视为潜在写操作并申请全局锁？
2. Schema 校验和权限判断有什么区别？
3. 为什么文件读取使用 `asyncio.to_thread`？

## 13. 参考答案

1. 元数据未知时采用 fail-closed，宁可保守串行，也不冒并发副作用风险。
2. Schema 判断参数“是否合法”；权限判断合法的操作“是否允许执行”。
3. 普通文件 API 是同步的，放到线程中可减少阻塞异步事件循环。
