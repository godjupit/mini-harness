    # 第 2 章：从 pyproject.toml 理解安装与程序入口

    > 适用对象：刚开始学习 Python、第一次接触 Agent（智能体）运行框架的读者。  
    > 对应项目：`mini-openharness` 0.6.0。  
    > 建议做法：一边打开源码，一边按本章给出的行号和问题阅读。

    ## 1. 本章目标

你将学会从 `pyproject.toml` 判断：

- 项目使用什么 Python 版本；
- 依赖有哪些；
- 包从哪个目录构建；
- 命令 `mini-oh` 最终调用哪个 Python 函数。

## 2. 什么是 pyproject.toml

它是现代 Python 项目的核心配置文件。可以把它理解成项目的“身份证 + 安装清单 + 命令映射表”。

关键片段：

```toml
[project]
name = "mini-openharness"
version = "0.6.0"
requires-python = ">=3.10"
```

这表示：

- 安装后的包名是 `mini-openharness`；
- 当前版本为 0.6.0；
- Python 至少要 3.10。

## 3. 依赖告诉你系统边界

```toml
dependencies = [
  "httpx>=0.27",
  "jsonschema>=4.20",
  "mcp>=1.28,<2",
  "python-dotenv>=1.0",
  "sse-starlette>=2.1.3,<3",
]
```

逐个理解：

- `httpx`：异步 HTTP 客户端，用来访问模型和 HTTP MCP 服务；
- `jsonschema`：验证模型传给工具的参数；
- `mcp`：MCP 客户端和协议实现；
- `python-dotenv`：从 `.env` 文件加载环境变量；
- `sse-starlette`：与流式传输相关的依赖，尤其服务于 MCP 示例或其传输栈。

只看依赖，你已经能推断项目包含网络请求、JSON Schema、MCP 和环境配置。

## 4. 开发依赖和运行依赖不同

```toml
[project.optional-dependencies]
dev = ["pytest>=8", "ruff>=0.5"]
```

`pytest` 用于测试，`ruff` 用于代码检查。它们不是程序正常运行的核心依赖，所以放在可选的 `dev` 组中。

安装命令：

```bash
pip install -e '.[dev]'
```

这里：

- `-e` 表示 editable install，修改源码后不用重复安装；
- `.` 表示安装当前项目；
- `[dev]` 表示同时安装开发依赖。

## 5. 找到真正的命令入口

最重要的配置：

```toml
[project.scripts]
mini-oh = "mini_openharness.cli:main"
```

冒号左边是模块：

```text
mini_openharness.cli
```

冒号右边是函数：

```text
main
```

因此，当你在终端输入：

```bash
mini-oh --demo
```

安装系统会帮你调用近似于：

```python
from mini_openharness.cli import main
main()
```

这就是源码阅读的第一个确定入口。

## 6. 为什么源码放在 src 目录

```toml
[tool.hatch.build.targets.wheel]
packages = ["src/mini_openharness"]
```

项目采用 `src layout`：

```text
项目根目录/
  src/
    mini_openharness/
      cli.py
      engine.py
      ...
```

这种布局避免测试意外导入当前目录里未安装的包副本。你必须正确安装项目，或临时设置 `PYTHONPATH=src`，Python 才能稳定找到包。

## 7. main 函数如何成为进程退出码

在 `cli.py` 文件末尾：

```python
if __name__ == "__main__":
    raise SystemExit(main())
```

`main()` 返回整数：

```text
0   成功
1   一般失败
130 用户中断，常见于 Ctrl+C
```

`SystemExit` 把这个整数变成操作系统看到的进程退出状态。

## 8. 从配置反推阅读顺序

根据 `pyproject.toml`，你的源码路径应该是：

```text
命令 mini-oh
  → mini_openharness.cli:main
  → cli._run
  → AgentLoop
```

所以接下来先读 `cli.py`，不是先读名字最酷的 `mcp_auth.py`。

## 9. 本章练习

1. 为什么执行源码测试前推荐 `pip install -e '.[dev]'`？
2. 把 `mini-oh = "mini_openharness.cli:main"` 翻译成人话。
3. 假设新增命令 `mini-trace = "mini_openharness.trace_cli:main"`，它会调用哪个文件中的哪个函数？

## 10. 参考答案

1. 它既安装包和运行依赖，也安装测试工具；editable 模式还让源码修改立即生效。
2. 用户运行 `mini-oh` 时，调用 `mini_openharness/cli.py` 模块中的 `main()`。
3. 调用 `src/mini_openharness/trace_cli.py` 中的 `main()`。
