    # 第 1 章：先读 README，建立项目地图

    > 适用对象：刚开始学习 Python、第一次接触 Agent（智能体）运行框架的读者。  
    > 对应项目：`mini-openharness` 0.6.0。  
    > 建议做法：一边打开源码，一边按本章给出的行号和问题阅读。

    ## 1. 本章目标

读完后，你应当能用自己的话解释：

- Mini OpenHarness 是什么；
- 它有哪些主要能力；
- 哪些模块属于默认主链，哪些属于可选扩展；
- 为什么阅读源码之前要先看 README。

## 2. README 不是“宣传页”

初学者常把 README 当作安装说明，扫两眼就跳过。对源码阅读而言，README 更像一本书的封面、目录和摘要。它告诉你作者希望这个项目被怎样理解。

打开项目根目录的 `README.md`，先只看以下位置：

```text
开头：项目定位和架构图
“30 秒运行”：最短可执行路径
“核心代码导航”：作者认为哪些文件最关键
“安全边界与非目标”：项目刻意不做什么
```

## 3. 用一句话定义项目

`pyproject.toml` 中的描述是：

```text
A small, interview-ready coding agent harness
```

可以翻译为：一个体量较小、适合面试讲解的编程 Agent 执行框架。

“harness”可以理解为“把各个零件接起来并负责运行的支架”。模型本身不是这里的重点，重点是怎样可靠地组织：

```text
模型 → 工具 → 权限 → 结果 → 下一轮模型
```

## 4. 先认识默认能力

项目默认注册三个本地工具：

```text
read_file   读取工作区文件
list_files  列出工作区文件
write_file  写入工作区文件
```

只靠这三个工具，模型已经可以完成最小的代码仓库查看和编辑流程。

在此基础上，项目还提供可选模块：

```text
Hooks            在关键生命周期点检查或修改行为
ContextCompactor 对过长历史做压缩
ArtifactStore    把超长工具输出放到文件
Trace            记录整个运行过程
Skills           按需加载额外说明
MCP              接入外部工具服务器
Docker Sandbox   在隔离容器中运行 shell
```

请注意“可选”二字。理解主链时，暂时把这些模块当成插件，不要一开始全部追进去。

## 5. 第一张心智地图

```text
cli.py
  │ 创建
  ├─ Provider：和模型 API 交流
  ├─ ToolRegistry：保存可用工具
  ├─ PermissionPolicy：决定能否执行
  ├─ HookRegistry：运行扩展检查
  ├─ ContextCompactor：压缩历史
  ├─ ArtifactStore：保存大输出
  └─ TraceWriter：记录事件
          │
          ▼
      AgentLoop
          │
          ├─ 请求模型
          ├─ 执行工具
          ├─ 把结果加入 messages
          └─ 判断是否完成
```

这张图暂时比任何单行代码都重要。后续每读一个模块，都把它放回这张图中。

## 6. 最小运行路径

执行：

```bash
mini-oh --demo --workspace . "解释这个项目"
```

大致发生：

1. CLI 解析参数；
2. 使用固定行为的 `DemoProvider`；
3. 注册默认工具；
4. 创建 `AgentLoop`；
5. 模型先请求 `list_files`；
6. 之后可能加载 Skill、读取 README；
7. 最终输出完成文字。

`--demo` 的意义不是模拟一个聪明模型，而是用确定的脚本验证完整工具链能够工作。

## 7. 读 README 时不要误解的词

### Agent

不是“自动运行的一段提示词”，而是拥有循环、状态和工具能力的运行系统。

### Provider

模型服务适配器。它把内部消息转换为某一种模型 API 的请求格式，再把返回结果转换回项目自己的 `ModelReply`。

### Tool

一个受控能力。模型只能“请求调用”，不能直接跳过程序执行任意代码。

### Replay

本项目的 safe replay 只是重新展示已经记录的 Trace，不会再次调用模型或工具，因此不会重复写文件等副作用。

## 8. 小白常见误区

**误区一：模型就是 Agent。**  
模型只是决策组件；循环、工具和安全边界由运行框架提供。

**误区二：文件多就要按字母顺序读。**  
源码阅读应按调用关系，而不是文件名排序。

**误区三：扩展功能越高级越应该先读。**  
MCP 和 OAuth 很吸引人，但它们最终仍然要进入统一工具链。主链不懂，扩展只会越读越乱。

## 9. 本章练习

1. 用一句话分别描述 `Provider`、`ToolRegistry`、`AgentLoop`。
2. 为什么先运行 `--demo` 比直接接真实 API 更适合学习？
3. 把上述心智地图手抄一次，并给每个方框写一句职责。

## 10. 参考答案

1. Provider 负责模型协议适配；ToolRegistry 负责注册和执行工具；AgentLoop 负责反复协调模型和工具。
2. Demo 行为确定、无需网络和 Key，出现问题时更容易判断是框架还是外部 API。
3. 重点不是画得美，而是能指出“谁创建谁、谁调用谁”。
