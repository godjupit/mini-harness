    # 第 16 章：理解 Docker Sandbox 隔离执行

    > 适用对象：刚开始学习 Python、第一次接触 Agent（智能体）运行框架的读者。  
    > 对应项目：`mini-openharness` 0.6.0。  
    > 建议做法：一边打开源码，一边按本章给出的行号和问题阅读。

    ## 1. 本章目标

阅读：

```text
src/mini_openharness/sandbox.py
tests/test_sandbox.py
```

## 2. 为什么 shell 工具风险很高

一个普通 shell 可以：

- 删除文件；
- 读取环境变量；
- 访问网络；
- 启动大量进程；
- 修改宿主系统。

因此项目不提供“失败时退回宿主机 shell”的逻辑。启用 `--sandbox-shell` 时必须有 Docker 和指定镜像，否则明确失败。

## 3. 一次命令一个临时容器

`DockerSandbox.run()` 为每次调用生成唯一容器名，执行：

```text
docker run --rm ... image /bin/sh -lc <command>
```

命令结束容器删除。这样不同调用不共享容器内部状态，主要持久状态只有挂载的 workspace。

## 4. 核心隔离参数

`build_argv()` 包含：

```text
--network none          禁止网络
--cpus / --memory       限制 CPU 和内存
--pids-limit            限制进程数量
--cap-drop ALL          移除 Linux capabilities
--security-opt no-new-privileges
--read-only             容器根文件系统只读
--tmpfs /tmp            提供有限临时空间
--user uid:gid          不以容器 root 身份写工作区
```

Workspace 绑定到 `/workspace`，作为命令工作目录。

## 5. 工作区仍然可写

容器隔离不等于所有文件只读。Sandbox Tool 被声明为变更工具，并对整个 workspace 申请树级写锁：

```python
ResourceAccess("fs:<workspace>", "write", tree=True)
```

因为任意 shell 命令可能修改任意工作区文件，无法像 `write_file` 那样精确知道目标路径。

## 6. 秘密文件遮蔽

项目寻找 workspace 中 `.env*` 文件，排除 `.env.example`，然后在容器对应位置挂载 `/dev/null`。

OAuth 目录则覆盖为权限为 000 的 tmpfs。

这意味着即使整个工作区被挂载，常见运行秘密仍被额外遮蔽。

## 7. 超时和取消

超时时：

1. `docker rm -f <name>`；
2. 停止本地 docker CLI 子进程；
3. 返回 `is_error=True` 的 ToolResult。

任务被取消时也执行清理，再向上重新抛出取消异常。

清理顺序很重要，否则只杀本地 CLI 进程，容器可能仍在后台运行。

## 8. 输出处理

标准错误合并到标准输出，统一解码；超过 12,000 字符进行截断。之后 Engine 的 ArtifactStore 还可能进一步处理其他大输出。

返回码非 0 时设置 `is_error=True`，但仍把命令输出交回模型作为 observation。

## 9. Sandbox 不是绝对安全

Docker 隔离降低风险，但仍依赖：

- Docker daemon 的安全；
- 镜像内容；
- 宿主挂载配置；
- Linux/平台实现；
- 工作区本身是否含敏感内容。

不要把 Sandbox 理解成数学意义上的完全隔离。

## 10. 为什么不自动 pull 镜像

`ensure_available()` 只检查镜像，缺失时要求用户显式拉取。自动拉取会引入网络、副作用、等待和供应链选择，项目把决定留给操作者。

## 11. 本章练习

1. 为什么 Sandbox Tool 对整个工作区加写锁？
2. `--network none` 解决什么风险，不能解决什么风险？
3. 为什么超时后要删除容器，而不只是取消 Python task？

## 12. 参考答案

1. 任意 shell 命令的文件副作用无法精确静态判断。
2. 它阻止容器直接联网，但不能防止修改已挂载工作区或利用 Docker/内核漏洞。
3. Python task 停止不保证外部容器停止，必须显式清理真实资源。
