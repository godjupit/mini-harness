## 2. 为什么要并发工具调用

模型可能在一轮同时请求：

```text
读取 README.md
读取 pyproject.toml
读取 tests/test_engine.py
```

这些读取互不冲突，依次执行会浪费时间。`asyncio.gather()` 让调用同时开始。

但以下操作不能盲目并发：

```text
写 a.txt
同时读 a.txt
```

读到旧内容还是新内容会变得不确定。

## 3. ResourceAccess 描述副作用

```python
ResourceAccess(key="fs:/repo/a.txt", mode="read")
ResourceAccess(key="fs:/repo/a.txt", mode="write")
```

字段：

- `key`：逻辑资源；
- `mode`：read 或 write；
- `tree`：是否代表整个目录树。

例如列目录：

```python
ResourceAccess("fs:/repo/src", "read", tree=True)
```

它与写入 `/repo/src/a.py` 冲突。

## 4. 冲突规则

`_resources_conflict()` 的核心逻辑：

```text
read + read          不冲突
只要涉及 write：
  同 key             冲突
  * 全局资源          冲突
  tree 包含子资源     冲突
其他不同资源          不冲突
```

因此：

```text
写 a.txt + 写 b.txt       可并发
读 a.txt + 读 a.txt       可并发
读 a.txt + 写 a.txt       等待
读目录树 + 写树内文件      等待
```

## 5. ResourceLockManager 怎样等待

它内部使用 `asyncio.Condition`：

1. 请求者检查资源是否可用；
2. 不可用则异步等待通知；
3. 可用时把自己的资源加入 active 列表；
4. 离开 `async with` 时移除并 `notify_all()`。

使用方式：

```python
async with self._resource_locks.acquire(resources):
    result = await self.tools.execute(...)
```

上下文管理器保证即使工具抛异常，也会进入 `finally` 释放锁。

## 6. _execute_timed 的实际顺序

```text
记录开始时间
→ pre_tool Hook
→ 使用 Hook 修改后的参数
→ 解析资源
→ 等待并获得锁
→ ToolRegistry.execute
→ 释放锁
→ post_tool Hook
→ 返回 ToolResult + elapsed_ms
```

一个容易忽略的点：pre Hook 如果改了路径，资源锁和权限判断都必须基于修改后的路径，而不是原始路径。

## 7. 并发完成顺序不等于返回顺序

```python
await asyncio.gather(task1, task2, task3)
```

即使 `task2` 最先完成，`gather` 返回列表仍按参数顺序排列：

```text
[result1, result2, result3]
```

这对工具协议很重要。AgentLoop 用 `zip(reply.tool_calls, timed_results)` 配对结果，必须保持模型原始调用顺序。

## 8. 取消如何工作

`_execute_all()` 同时创建：

```text
gather_task：所有工具调用
cancel_task：等待 cancel_event
```

使用：

```python
await asyncio.wait(..., return_when=FIRST_COMPLETED)
```

如果取消信号先到：

1. 取消 gather task；
2. 等待被取消任务清理；
3. 返回 `None`；
4. AgentLoop 发出 `cancelled`。

这是协作式取消，不是粗暴杀死整个 Python 进程。

## 9. 为什么记录 resource_wait/acquired/released

并发问题很难调试。Trace 中记录：

```text
工具请求哪些资源
等待了多久
持有锁多久
何时释放
```

如果某个工具看起来“卡住”，你可以判断它是在执行，还是在等待冲突资源。

## 10. fail-closed 的资源策略

若工具不存在、没有正确资源解析器，或解析器出错：

```python
ResourceAccess("*", "write", tree=True)
```

这相当于全局写锁。保守但安全：不能确定副作用时，不让它与其他操作并发。

## 11. 本章练习

判断下列是否可并发：

1. 读 `a.txt` 与读 `a.txt`；
2. 写 `a.txt` 与写 `b.txt`；
3. 列出 `src/` 与写 `src/a.py`；
4. 一个未知工具与任意写工具。

## 12. 参考答案

1. 可以；2. 可以；3. 不可以，目录树读锁包含子文件；4. 不可以，未知工具使用全局写锁。
